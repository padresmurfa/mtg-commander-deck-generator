# Retro — Sprint 1.3 — Classes, dominance, enrichment

**Epic:** E1 Card pipeline · **Gate:** none

## The measurement

Nobody had taken it, and the sprint was deliberately left un-split until
somebody did. Everything the search does is sized by this number.

| | count | ratio |
| --- | ---: | ---: |
| Commander-legal, representable cards | 29,681 | — |
| **Equivalence classes** | **8,524** | 3.48× |
| **After dominance chaining** | **2,698** | 3.16× again, **11.0× overall** |
| …tiered (absorbed a dominated class) | 902 | 33% of survivors |

Design §7.1 guessed a ~400-card candidate pool would collapse toward ~150 — a
2.7×. Over the whole legal pool, equivalence alone gives 3.48×, and dominance
takes it to 11×. The order of magnitude was right; the figure was about a
different pool and should not have been quoted as though it were general.

**And the same condition G1 carries applies here.** The class key is what the
model can *see*, and 90.3% of clauses are inert — so a large part of that 11× is
cards collapsing into "a 2/2 for {1}{G} that does nothing observable". That is
§7.1 working exactly as designed, and it means **the class count is a function of
how narrow the simulated phases are, and will rise when E3 widens them.** It is
recorded beside the inert share for the same reason the coverage fraction is.

Other numbers worth keeping:

- **Only 36 classes were unpriced**, against 3,849 unpriced *cards* — an unpriced
  card almost always shares a class with a priced one, and the class takes the
  cheapest member. 21 imputed by dominance, 15 left explicitly unpriced.
- **Skill floors**: 16,346 ask nothing, 3,923 basic, 2,917 careful, 5,907 expert,
  588 master. The expert fifth is instants, modal spells and X costs; the 2%
  master tail is wheels, wipes and stax.
- **The table is 2.9 MB** for 29,681 cards including every name and oracle id,
  written in 4.2s from a 595 MB export.

## What the ordering turned out to be

**The 32-byte struct came first, not last.** It was carried out of 1.2 as
unfinished business and turned out to be the prerequisite for the whole sprint,
because §7.1 does not class cards *by* the struct — the struct **is** the class.
Waiting for the opcode payload to settle was right, but the reason recorded in
the 1.2 retro ("pack the bits once") was the smaller half of it.

Two things had to exist before the key could:

- **Power and toughness were never parsed.** Without them a 1/1 and a 7/7 of the
  same cost are one class. `*`, `1+*` and `∞` are marked rather than read as
  zero, which would have put Tarmogoyf in a class with the worst creature in
  Magic.
- **The mana scan did not record *which* mana a producer makes.** Without that
  every land in Magic is one class and the headline number would have been about
  nothing. A dual's two symbols are alternatives rather than a quantity — the
  same shape as 1.2's dual-land bug, caught this time by a test that failed first.

## Defects found, and how

Three, and none by a failing test written in advance.

**The roster was built in class order, not preference order.** Merging a
dominance chain iterated classes by index, which puts the *dominated* card at the
top of the roster whenever its index happens to be lower — exactly inverting the
ordering a tiered class exists to encode, so expansion would have taken the worse
card first. Found by writing the test for the case where the better card is built
second, which is the case a symmetric example never reaches.

**`mf_precons_distinct_cards` was quadratic** and carried a comment claiming it
was "linear in practice". 361 million `strcmp` calls for a number printed once.
The comment was written in the same minute as the code and was wrong then.

**`mf_table`'s two size constants were both wrong** — header 32 against an actual
36, record 40 against 41 — caught by counting them out loud rather than by a
test, because a wrong constant here produces a file that reads back fine and only
fails when something else writes one.

## Mutation testing

The method did most of the work this sprint, and the shape of the result is worth
recording: **the first pass on dominance caught 7 of 11, and every survivor was a
rule that no test could distinguish because a *different* rule happened to reject
the same case.** A vanilla 5/5 does not dominate a mana dork for two independent
reasons, so deleting either one changed nothing. Each needed a case constructed
so that only the rule under test could reject it — same colours but different
amounts, same opcodes but different colours, everything equal but the type line.

| Module | Caught | Note |
| --- | --- | --- |
| `mf/opcode` (report) | 5/5 | |
| `mf/metacard` | 11/11 | including "put price in the key", which splits the elves |
| `mf/classes` | 21/21 | after three rounds; 7/11 on the first |

Every pip of the cost now has its own row, on the same standard the opcode marker
list is held to, and so does every entry in the skill-floor list.

## Design amendments

Applied with this retro:

1. **§7.1 gains the measured figures** and the note that ~150 described a
   candidate pool rather than the legal set.
2. **§7.9 / spec `card_struct`** — the field list conflated two structs. It named
   `oracle_id` and `name` inside a 32-byte budget, which is impossible: an oracle
   id alone is 36 bytes. There are two things — the **functional identity**
   (20 bytes, the class key, what the simulation holds) and the **table record**
   (what preprocess writes, strings included). Corrected.
3. **§8 gains the binary table's format** and the note that the JSONL
   intermediate is gone.
4. **Skill floors** get their rule list recorded as spec rather than as prose.

## Revised risks

| Risk | Change |
| --- | --- |
| **The class count is narrow for the same reason G1 is** | ⚠️ New, and the direct successor to 1.2.1's metric hazard. 11× looks like a search-space win and is partly a statement about how little is simulated. Re-measure at E3 with the coverage figure |
| **Simulator-equivalence is coarser than real equivalence** | ⚠️ §7.1 says so and now it is load-bearing: 29,681 cards became 2,698 choices, so **expansion has to re-validate** or a deck handed to a player will contain a card the search never really considered. E4 owns this and must not treat the class as the card |
| **A classifier agrees with itself** | ↔ Unchanged and still the standing hazard. This sprint's defects were found by mutation and by counting, not by tests written in advance |
| **Dominance is deliberately rare** | ↔ Working as intended. The ≤ dollar cost half means most strictly-better cards do not dominate, which is what stops the relation displacing the budget option |
| **Precon prices are still hand-maintained** | ↔ Unchanged. Contents are solved (190 decks); the retail *price* table is 190 rows nobody has typed, and §7.5's acquisition path needs it |
