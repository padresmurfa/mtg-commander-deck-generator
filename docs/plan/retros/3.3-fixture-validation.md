# Retro — Sprint 3.3 — Fixture validation

**Epic:** E3 Solo evaluation · **Gates:** G4

## Headline

> **G4 could not be measured, because not one of the 190 precons can be built.**

The sprint did everything G4 needs: the corpus is transcribed and tracked, the rank correlation is
written and checked against hand-computed cases, the precon lists resolve through the card table,
and the thresholds were committed **before the data existed in the tree** — which is the only form
of "fixed in advance" a repository can show rather than assert.

Then the corpus came out empty. Best case across all 190 precons is **one** missing card; the mean
is 9.3 and the worst is 22. **Nineteen percent have an unrepresentable commander**, which alone
drops 13 of the 48 decks that clear §13.2's `n ≥ 100` filter.

**The finding is about G1's metric, not G4's.** G1 measures *clause* coverage and reads 0.9301.
Per-*deck* completeness at that coverage is **0 of 190** — with ~93% of clauses covered and a
hundred cards to a deck, the chance all hundred resolve is nil. G1 already carries one written
hazard, that it rises when *less* is simulated. This is a second and sharper one:

> **Clause coverage says nothing about whether any real deck can be built**, and the two numbers
> were being read as though one implied the other.

**The defect that hid it was mine, and it is the more instructive half.** The first resolver filled
each hole by repeating the last resolved card, so every deck came out at a hundred and the gate ran
happily, producing **ρ = −0.0137 over 35 decks**. That number is a diagnostic and is *not* the gate:
those decks carried a mean of 11.3 invented cards each, concentrated in whatever card happened to be
last, which distorts the curve this model actually simulates. §13.2 uses precons because a precon is
"one exact, published, unambiguous list"; a deck that is 11% invented is not that one. Refusing to
patch is what made the real state visible, and a patched fixture is a gate reporting a verdict about
something else.

## Gate validation

### G4 — precon rank correlation

| | |
| --- | --- |
| **Question** | Does the objective rank real decks in the right order? |
| **Threshold** | ρ ≥ 0.35 **and** ρ·√(N−1) ≥ 2, at 2,048 games per deck, on precons with n ≥ 100 — all committed before the data existed |
| **Measured** | corpus 48, **scored 0**, unjoined 48, mean gap 11.8 cards. ρ = 0.0000, z = 0.00 |
| **Outcome** | **DEFERRED** |

**Why deferred and not failed.** `FAIL` is a claim about the objective — that it orders real decks
no better than chance. A corpus that produced no decks supports no claim about the objective at all.
The guard runs *before* the thresholds, and its boundary is **two**, not one: a single deck is an
ordering of one thing, and ρ would come back zero, fall into `FAIL`, and be read as "ranks decks
backwards". This is 2.1's defect — a gate reporting agreement it never observed — in a new place.

**The pre-registration anticipated three ways the number could be ambiguous and missed the way it
could fail to exist.** The three named blind spots were flood and screw uncaught (3.2), the
deck-differential aggregation error (3.1), and 4-player data against a 2-player model (§13.2). None
of them is why G4 deferred. Worth recording as a limit on pre-registration itself: it protects the
threshold, and it does not make you think of everything.

**What has to happen before G4 can run**, named and not done, because choosing it *after* seeing
ρ = −0.0137 is the move pre-registration forbids:

1. **A pre-registered substitution semantics.** An unrepresentable card still has a mana cost and a
   type, and this model is mostly about mana — a same-cost vanilla permanent preserves the curve
   exactly and loses only what the model already cannot see. That is a modelling decision with a
   real argument, and it must be written down before it is measured.
2. **Or grow the opcode set**, which is G1's own failure branch and now has a much sharper argument
   for it than 0.9301 ever gave.

Either is a sprint. **Sprint 3.3.1 is inserted for it**, on the 0.2.1 / 1.2.1 / 5.0 precedent, and
E4 does not start first: building the search against an unvalidated objective is exactly what G4
exists to prevent.

## Revised risks

**Scarier.**

- **E4 is blocked on a gate that has not answered.** The plan's own rule is that a gate is placed as
  early as the dependency graph allows, because the point is to be wrong cheaply. Proceeding to the
  search epic with an unvalidated objective spends the saving.
- **The clock, still.** G4 was expected to be the first outside check on 3.2's three findings. It
  cannot be, yet — so "a null-opponent model prices position at zero" remains untested against
  anything external.

**New.**

- **A metric can be sound and answer a question nobody asked.** G1 is correctly computed and
  correctly reported and does not bound the thing that turned out to matter. Ask what a coverage
  number is coverage *of*, and what it would have to be for the next step to work.
- **A fixture that patches itself hides the state of the world.** The hole-filling resolver was
  three lines, looked defensive, and turned an empty corpus into 35 plausible decks and a number.
  Prefer refusing.

**Stopped mattering.**

- **Whether the win-rate table could be obtained at all.** It could; it is transcribed, tracked and
  checksummed. The blocker was never the data.
