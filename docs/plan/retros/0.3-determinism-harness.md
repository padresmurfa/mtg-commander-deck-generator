### Not delivered

Nothing from the sprint scope. Three things a reader should know anyway:

- **The thread axis has no threads in it.** Threading is sprint 6.1. The axis partitions the work
  the way a thread pool would and visits the partitions last-first, which exercises the property
  that actually matters — the digest must be invariant to partition order — and none of the ones
  that need real concurrency. When 6.1 lands, this test does not change; it just gets a real
  execution model underneath it.
- **`mf/trial` is a stand-in and says so in its own header.** Shuffle, draw, add. It has the *shape*
  of an evaluation and none of the rules of Magic. It exists to be deleted in E2, and the golden
  files are regenerated then.
- **`make hook` has no user yet.** It installs a pre-push hook running `make check`, and it is the
  entire mitigation for having no hosted CI. Opt-in on purpose; nothing enforces it.

## T0 — the CI decision, finally made

**Decided: local only. `make check` is the gate, and there will be no hosted CI.**

Deferred in 0.1 and again in 0.2, both times because the digests it would enforce did not exist.
That reason expired this sprint, which is why it was T0 rather than T10 — and the answer turned out
not to depend on the digests at all.

The deciding reason is that **the build is pinned to one machine.** The spec fixes
`-mcpu=apple-m1`; the design fixes the target host to one Apple-silicon laptop; and the determinism
invariant is *defined against that target*. A hosted runner would compile a different program with a
different toolchain, so a green tick there would be assurance about something else. That is not
weaker CI — it is CI of the wrong thing.

The standing instruction on this repo also forbids adding a cloud dependency, and that alone would
have settled it. Worth recording that the technical answer agrees independently, so this is a
constraint the project happens to want rather than one it is working around.

What it costs, plainly: nothing enforces the gate on a machine that has not run it. `make hook` is
the mitigation and it is opt-in. Revisit if this stops being one person on one machine — that is the
condition all three reasons rest on.

### One substitution worth naming

T1 was planned as "Philox-style or PCG". It was built on **splitmix64** instead, and the reason is
testability rather than quality. Philox has published test vectors, but I could not verify them from
memory and a "known-answer test" whose known answers came out of my own implementation is not a test
of anything. splitmix64's first outputs from state zero are widely published, I could check them
against an independent reimplementation, and the per-stream sequence *is* splitmix64 unchanged — so
one genuine external anchor covers the mixer, and `mf_rng_state` is public so that the claim "a
stream is splitmix64 and a counter is a seek into it" is a test rather than a comment.

Only the derivation of a stream's starting state is bespoke, and that is the part the property tests
cover.

## What mutation testing bought this time

The coverage floor found nothing this sprint — every module reached 100% line on the first honest
attempt, because there is very little branching in a hash or a bump counter. **Mutation testing
found four real gaps**, three of which were tests that passed for the wrong reason:

- **A shift test that only looked forwards.** `two_streams_are_not_shifts_of_one_another` compared
  stream *s* advanced by *k* against stream 0. The mutation made stream *s* equal stream 0 advanced
  by *s* — a shift in the direction the test did not look — and it survived. Rewritten as a
  collision test over a window, which has to guess neither direction nor magnitude. Two 64-bit
  values colliding by chance in that window is not going to happen; a collision means the streams
  are related.
- **The seed and the stream were interchangeable.** Fold them with a bare xor and run 7 of seed 3
  *is* run 3 of seed 7 — two runs a user believes are independent, silently identical. Nothing
  caught it until a test said so by name.
- **The run layer folded in reverse and nothing noticed.** The existing test fed the layers in two
  different orders and compared; reversing the *fold* changed both sides identically. Fixed by
  rebuilding the expected value by hand in ascending order. The fold order is part of the format —
  a golden file recorded under one and checked under the other would disagree about a run that had
  not changed.
- **The reduction's slot count was untested.** The test compared a 2-slot reduction against a
  4-slot one padded with zeros, which differ anyway because more slots means more values. The
  property that actually needs the count is that *two* reductions fed into one layer must not read
  as one larger reduction over the same values. Rewritten as that.

**Two mutations survived, and they are recorded rather than papered over.** Both weaken the digest's
internal mixing — dropping the length from one lane, and removing the cross-lane stir — without
changing any behaviour the contract exposes. That is the nature of a hash: its *quality* is not a
property a test can assert, only its contract is. Inventing a test to kill them would have pinned an
implementation detail and taught a future reader that the detail is load-bearing when it is not.

Two things also needed a seam built specifically so a claim could be tested rather than asserted:
`mf_rng_reject_below`, because the bias a modulo fold leaves is one value in 2^64 and no sample size
would ever find it; and `mf_rng_state`, because "a counter is a seek into splitmix64" is otherwise
perfectly self-consistent however wrong the step size is.

## Revised risks

| Risk | Change |
| ---- | ------ |
| **No CI** | ⚠️ New, and accepted with the reasoning above. The gate exists and is complete; nothing enforces that it ran. `make hook` is opt-in and nobody has run it |
| **The matrix proves less than it appears to** | ⚠️ New. Six green combinations on a workload with no game semantics and no real threads. It proves the *harness* is sound — which is the whole point of building it now — and proves nothing yet about a simulator that does not exist. The honest reading is "the instrument is calibrated", not "the result is deterministic" |
| **`mf/trial` becomes permanent** | ⚠️ New, and mild. Stand-ins that work have a way of staying. Mitigated by saying so in its own header, in the spec, and here: it is deleted in E2 |
| **`_FORTIFY_SOURCE` folded branches cap coverage** | ↔ 21 of 22 residual branches. Unchanged in kind; the new modules barely branch |
| **Pre-optimising the memory layer** | ↔ Unchanged. `mf/reduce` is the first caller the pool did not have, and it took an arena without argument |
| **Coverage floor unreachable in C** | ↓ Line 100%, function 100%, branch 97.25%. The one real uncovered branch is still the `_exit` itself |
