### The 0.1 seam was superseded by its own logic

Sprint 0.1's headline was the allocation seam: out-of-memory branches no test could reach, made
reachable by injection, worth 8 points of branch coverage. That retro said the coverage floor "did
not just measure the design, it changed it."

It changed it again, further, in the opposite direction. The seam made the OOM branches *testable*;
this sprint made them *nonexistent*. `mf_arena_alloc` cannot fail, so no caller checks, so there is
no branch, so there is nothing to inject into. `src/alloc.c`, `include/mf/alloc.h` and
`tests/test_alloc.c` are gone, and so is every OOM sweep that ran over them.

The lesson generalises and is worth carrying: **a testable failure path is better than an untested
one, and no failure path is better than either.** The seam was the right answer to the question
"how do I test this branch?" It was the wrong question. The right one was "why is there a branch?"

What survives is the half about genuine I/O. The environment really can refuse a write, and the code
really must respond, so those seams remain and gained three more (a pre-opened artifact, the panic
hook, and closing a descriptor under a live `FILE*`).

### Two more branches deleted rather than tested

Both were made dead *by* the port, which is the pattern to watch for after any refactor:

- `jw_raw`'s poison check. It existed because a failed reallocation could poison the writer
  mid-string. An arena cannot fail, so the only remaining way to poison is a structural error, and
  every caller already checks for that first.
- The `for (prec = 15; prec <= 17)` loop in number formatting. `%.17g` always round-trips, so the
  loop could never run out — its exit branch was unreachable. Three straight-line statements say the
  same thing with every branch reachable.

## What the coverage floor bought this time

Two genuine defects, both found by a test that failed rather than by reading:

- **Cache-line alignment was computed from the offset, not the address.** `mf_arena_alloc_aligned`
  rounded `used` up to the requested boundary, which is only the same thing as aligning the pointer
  if the arena's payload happens to start aligned — and `calloc` promises 16 bytes, not 128. The
  test asked for a 128-byte-aligned block and got one at address ≡ 48. Fixed by aligning the payload
  start at creation, which also gives every arena a cache-line-aligned base for free (sprint 6.3
  will want that).
- **The stream reader reserved 8 KB up front.** A one-byte config file was charged eight kilobytes
  of arena — and since the arena is sized by its high-water mark, the overcharge would have outlived
  the read and inflated every future run's arena. Found by a test whose 4 KB arena died on a
  one-byte file. It now starts at 64 bytes and doubles in place.

Neither would have been caught by review. The first looks right; the second *is* right, in a world
where the memory does not have to be paid for.

## Revised risks

| Risk | Change |
| ---- | ------ |
| **`_FORTIFY_SOURCE` folded branches cap coverage** | ↔ Unchanged in kind, better understood in size. **18 of the 19 residual branches are folded.** The other one is `if (g_hook)` in `mf_panic` — the actual `_exit`, which by definition cannot run in a process that has to survive to report it. `tests/smoke.sh` covers it with real processes and real exit codes |
| **Arena sizing is a guess that has to be right** | ↓ Largely retired, which was the point. The smoke test starts a run at 64 KiB against work needing 1 MiB and watches it climb to 1.25 MiB across five relaunches and persist there. The second run fits first time |
| **Catching a fatal in tests leaks what the dying process abandoned** | ⚠️ New, and deliberately not papered over. `MF_EXPECT_PANIC` longjmps past cleanup, so anything the panicking code owned outside the test's own arena leaks — LeakSanitizer is right to say so. The rule adopted: **do not catch a fatal that owns memory the test cannot reach.** One worker test moved to `smoke.sh` for exactly this reason, and lost nothing, because the lines it covered were covered elsewhere |
| **Pre-optimising the memory layer** | ⚠️ New, accepted with eyes open. The shape is built for a fast implementation that does not exist yet, and three `TODO(perf)` entries name the sprint that resolves each. The risk is that the shape turns out wrong for reasons only a real hot loop reveals. Mitigated by keeping the interface narrow — nothing outside `mf/arena` observes *when* memory is zeroed, only that it is |
| **Two processes is more machinery than one** | ⚠️ New. A spawn, a resolved config file, a report file, and a retry loop, all to solve a sizing problem. Judged worth it because the alternative — a worker that catches its own out-of-memory — is the thing the whole design removes. Kept honest by `--no-spawn`, which runs the identical work in one process and is smoke-tested |
| **Coverage floor unreachable in C** | ↓ Reduced again. 100% line and 100% function this time, with fewer error branches to chase because there are fewer error branches |
