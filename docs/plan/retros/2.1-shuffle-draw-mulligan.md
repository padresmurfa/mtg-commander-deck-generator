## Gate validation — G2

| | |
| --- | --- |
| **Question** | Does the sampler converge to closed-form hypergeometric truth? |
| **Tolerance** | **5σ per cell**, `SE = sqrt(p(1-p)/N)` — **fixed before anything was measured** |
| **Measured** | worst cell **2.43σ** (7 decks × 8 cells, N = 100,000, seed 0) |
| | worst cell **3.19σ** (9 decks × 8 cells, N = 1,000,000, seed 20260809) |
| | worst cell **1.67σ** (the golden's seed) |
| **Call** | **PASS** |

The tolerance and the scope were both written into the sprint document before a
line of the sampler existed, because **a threshold chosen after seeing the
result is not a gate**. 5σ rather than 3σ because the gate grades every cell of
every deck at once: at 3σ, ~72 cells would false-alarm about one run in nine,
while at 5σ the family-wise rate is ~3e-5. The standard error needs no result to
compute — only the sample size.

### What the gate covers, decided in advance

**The shuffle and the draw. Not the mulligan.** The hypergeometric is exact for
one seven-card draw from a shuffled library; the London mulligan is a decision
procedure with no comparable closed form. It is checked by properties instead —
it terminates, the hand shrinks by one per mulligan, seven are always drawn.

Stating that up front matters because the alternative is a gate that *sounds*
like it validated the opening phase and validated a third of it. That is exactly
the overclaim 1.2.1 spent a sprint unwinding on G1, and it was cheaper to avoid
than to correct.

### The 3.19σ, and why it was chased

At N = 1,000,000 the worst of 72 cells came in at 3.19σ. That passes, but it is
high for a worst-of-72 — the expected maximum of 72 standard normals is about
2.7σ, and 3.19 is roughly a one-in-ten event. **A systematic bias in the
shuffler is the defect that survives to the end of a project**, because it never
fails: it just makes every later number wrong in the same direction.

So it was interrogated rather than accepted. Across eight seeds, that cell:

| seed | signed σ |
| ---: | ---: |
| 1000003 | +0.49 |
| 2000006 | −0.27 |
| 3000009 | −0.10 |
| 4000012 | +0.08 |
| 5000015 | +0.81 |
| 6000018 | −1.67 |
| 7000021 | **−3.21** |
| 8000024 | +0.05 |

Mean **−0.48σ**. It wanders both directions and one seed produces the mirror
image of the original excursion. Noise, not bias — and the ten minutes were the
right ten minutes, because the alternative was taking a one-in-ten tail on trust.

## The defect the unit suite found

**With zero samples, the gate passed.** The standard error is `sqrt(p(1-p)/0)` =
infinity, every deviation divides down to 0σ, and the result reported agreement
it had never observed. A gate that passes without measuring anything is the one
failure mode a gate cannot be allowed to have, and it was two lines from
shipping. Now `samples > 0` is a precondition of passing rather than an
assumption about callers.

## What the modelling required

**The commander is not in the library and is not drawn.** A Commander deck is 99
cards plus one in the command zone. Shuffling 100 would shift every land
probability by one card in ninety-nine — about 1% relative — which is well
inside what looks like Monte Carlo noise and would have made G2 pass anyway at
this sample size. It is the kind of error a gate does not catch, so it is a
property the deck type enforces instead.

**The `uint8` indices in the invariant are into the per-deck table**, not the
29,681-card global one. Two levels of indirection, and confusing them is how a
32-bit index reaches a hot path. The header says so because the invariant's
wording alone does not.

## Mutation testing

The shuffle was the target, since a shuffler passes plausible tests while being
subtly wrong.

| Mutation | Result |
| --- | --- |
| The classic Fisher-Yates bug — draw below `count`, not `i+1` | **caught** |
| Never swap the last element | **caught** |
| Swap with a fixed partner rather than a drawn one | **caught** |
| Modulo fold instead of rejection | **survives, correctly** |

The survivor is the interesting one and it is not a gap. At n = 99 the modulo
bias is one value in 2⁶⁴; no sample size would ever find it, which is precisely
why `mf_rng_reject_below` exists as a public function asserted as *arithmetic*
rather than statistically (spec `determinism.mechanisms.bounded_draw`). A test
that claimed to catch it would be lying.

## Design amendments

1. **§13.1 gains the measured result** and the tolerance, with the note that the
   tolerance was fixed in advance.
2. **§5 gains the policy shape** — parameters rather than an interface — with the
   reason: the five rungs differ in numbers, not in kind, and the per-game path
   must stay free of indirect calls.
3. **Spec gains `analytic_agreement`** beside `opcode_coverage`, including what
   the gate does *not* cover.

## Revised risks

| Risk | Change |
| --- | --- |
| **G2 fails and the simulation core is wrong** | ✅ **Retired.** The sampler agrees with arithmetic across nine deck shapes and several seeds |
| **A gate that cannot fail** | ⚠️ New, and nearly shipped. The zero-sample pass was found by a test asking the question directly. Every future gate needs "what would make this pass vacuously?" asked of it |
| **The mulligan is unvalidated against truth** | ⚠️ Known and accepted, deliberately. It has no closed form; G3's policy-gap measurement is where the keep rule earns or loses its place |
| **The bottoming rule is a guess** | ⚠️ New. "Excess lands first, then the most expensive spell" is plausible and untested against anything — no oracle, no fixture. 2.3 measures policies; this is one of the things it should measure |
| **`mf/trial` is still the determinism harness** | ↔ Unchanged. It exists to be deleted once a real opening phase exists; that is 2.2, not here |

## What Tagger was for

Recorded here because `reference/legacy-ts/` is now one sprint from deletion and
this is the only place the intent is written down.

**Scryfall Tagger** is a community-maintained tagging system with two vocabularies:
*oracle tags* (otags — what a card **does**: `ramp`, `removal`, `tutor`,
`card-draw`, `sacrifice-outlet`) and *art tags*, which are irrelevant here. The
legacy tree consumed otags for role classification — how many ramp pieces, how
many removal spells a deck holds — which is what design §7.4 wants to sharpen
**skill floors** and what §3 wants for role targets.

**What 1.3 shipped instead** is a list of oracle-text markers. That is a weaker
signal in a specific way: it sees *wording*, not *function*. "Search your library
for a basic land" is recognised as ramp; a Signet is not, because it is a mana
rock whose text says nothing about lands. An otag would have caught both.

**The decision this leaves open** is whether to depend on a community dataset
with no stable API at all — Tagger has no documented public endpoint, and the
legacy code scraped its GraphQL. That is a dependency of exactly the kind
CLAUDE.md §3 is suspicious of, and the honest options are: scrape and vendor a
snapshot, hand-maintain a small otag table for the cards that matter, or accept
the weaker text markers and let G3 say whether they are good enough.

**EDHREC** is the other half and is easier: it is only ever wanted for data the
`no_popularity_prior` invariant forbids using as a prior. Its role needs
restating before anyone ports it, and it may simply not have one.
