# Sprint 0.2 — Memory & process model

**Epic:** E0 Foundations · **Gate:** none · **Status:** `done` — [retro](../retros/0.2-memory-process-model.md)

## Goal

Replace `malloc`/`free` ownership with arena allocation, replace out-of-memory *handling* with
out-of-memory *death*, and split the tool into an orchestrator process and a worker process so a
worker can die asking for a bigger arena and be relaunched with one.

## Why this, and why now

Three decisions arrived together, and they are the same decision seen from three sides.

**Environmental failure is not a branch.** A failed allocation in a batch simulator is not a
condition to recover from — there is nothing useful to do with half an arena. Handling it produces
error paths that exist only to be tested, on a machine with 32 GB of RAM where they will never fire
in anger. Sprint 0.1 went the other way, building an injection seam so those paths were reachable,
and the retro recorded it as a win. It was a win *given that the paths existed*. Deleting them is
strictly better than testing them: `mf_arena_alloc` cannot fail, so no caller checks, so there is
nothing to cover.

**Arenas make lifetime a property of the phase, not of the object.** The per-game path must not
allocate at all (`no_io_in_loop`), and the per-evaluation path must allocate in one bump and release
in one pointer reset. That is an arena. It also removes the entire class of use-after-free and leak
defects by construction rather than by sanitiser, and it is what E6 will need per thread anyway
(sprint 6.1 exit criteria already say "per-thread arenas").

**Arena sizing is discovered, not derived.** The honest maximum working set of an evaluation is not
knowable before the evaluation exists. So the failure mode is designed to be *self-correcting*: the
worker dies with a machine-readable report saying which arena, how big it was, and how much more it
wanted; the orchestrator grows the number, rewrites the config, and relaunches. The arena size is
not a guess that must be right, it is a cache that converges.

Doing this before sprint 0.3 rather than after is the cheap ordering: the determinism harness digests
whatever the program produces, and rewriting every module underneath a golden file means
regenerating every golden file. Arenas first, digests second.

**This is deliberate pre-optimisation, scoped as such.** The layer is built for the shape the
optimised version needs — pooled, pre-zeroed, single-threaded, stack-framed — and backed for now by
one `calloc` per arena. Every place where the fast version differs from today's version carries a
`TODO(perf)` naming what changes. Doing the shape now and the speed later costs one sprint; doing
both later costs a rewrite of everything built in between.

## Input from the 0.1 retro

- **The allocation seam is superseded, not abandoned.** Its lesson — a failure path no test can reach
  is a path nobody has checked — is honoured by removing the paths. What remains (arena exhaustion,
  backing-store refusal) is reachable without injection: ask for an arena of `SIZE_MAX`.
- **`_FORTIFY_SOURCE` folded branches** still cap branch coverage. Fewer error branches should raise
  the ceiling, since the residual is a fixed count against a smaller denominator.
- The **CI decision carries forward again**, to 0.3. It was deferred in 0.1 because output digests
  did not exist; they still do not.

## Exit criteria

- [x] No `malloc`, `calloc`, `realloc`, `free`, `strdup`, or `asprintf` outside the memory layer
- [x] Every module allocates from an arena passed in by its caller
- [x] Allocation failure and arena exhaustion terminate the process with a distinct exit code and a
      machine-readable fatal report
- [x] Arena stack frames release in O(1) and restore the zero guarantee
- [x] `mfsim` supervises `mfsim-worker`; an arena-exhaustion exit is retried at a larger size, and
      the resolved size is written back to the config
- [x] `make check` green at ≥95% line and branch

## Tasks

- [x] **T1 — `mf/panic`: fail-fast.** `mf_panic(code, fmt, ...)` and `mf_panic_arena(...)`, both
      `_Noreturn`, writing a human message to stderr and — when a report path is set — one JSON
      object naming the shortfall. Stable exit codes: `70` arena exhausted, `71` out of memory,
      `72` broken invariant. Exits via `_exit` so no atexit handler can turn a death into a hang.
      *Done when:* each code and message is asserted by a test, the report file parses as JSON with
      the right fields, and a run with no report path still dies cleanly.
- [x] **T2 — `mf/arena`: bump allocator.** Create/destroy, `alloc`, `alloc_aligned`, overflow-checked
      `array`, `grow_last`, `push`/`pop`, `reset`, and `used`/`cap`/`high_water`.
      *Done when:* allocations are always zeroed **including after a pop**, alignment is honoured,
      a `count × size` overflow panics rather than wrapping, exhaustion panics with the shortfall,
      `pop` restores the exact prior offset, and the high-water mark survives resets.
- [x] **T3 — `mf/pool`: pre-zeroed arenas.** Fixed-depth pool, `acquire`/`release`, and a counter of
      arenas created past the initial fill.
      *Done when:* acquiring from a full pool does not allocate, acquiring from an empty pool works
      and increments the counter, a released arena is reset and zeroed before reuse, and releasing
      beyond depth destroys rather than grows.
- [x] **T4 — `mf/mem`: the stdlib proxy.** Arena-backed `strdup`, `strndup`, `dup`, `sprintf`,
      `vsprintf`, `read_stream`, `read_file`. The one and only place that may call an allocating
      libc function.
      *Done when:* each returns arena memory, `sprintf` handles a result larger than its first
      attempt, `read_file` reports a missing file as NULL rather than panicking (a missing input is
      a user error, not an environmental one), and a grep for bare `malloc`/`free` outside
      `src/arena.c` finds nothing.
- [x] **T5 — Port `mf/json`, delete `mf/alloc`.** Parser and writer take an arena; `mf_json_free`
      and `mf_jw_free` disappear along with every `MF_ERR_INTERNAL` return.
      *Done when:* the existing json suite passes unchanged in meaning, `src/alloc.c`,
      `include/mf/alloc.h` and `tests/test_alloc.c` are gone, and `MF_ERR_INTERNAL` is unreferenced.
- [x] **T6 — Port `mf/config` and `mf/artifact`.** Both take an arena. Config gains `arena_bytes`,
      `arena_max_bytes` and `max_relaunch`, with ranges.
      *Done when:* the new keys round-trip through load → write → load, out-of-range values are
      rejected, and the artifact's fixed buffer comes from the arena rather than from `malloc`.
- [x] **T7 — Orchestrator and worker.** `mf/orch` with a **pure** growth planner (given a fatal
      report and a config, decide the next arena size or give up) and a launch seam so the retry
      loop is testable without spawning. `mfsim` spawns `mfsim-worker`; `--no-spawn` runs the work
      in-process.
      *Done when:* the planner's decisions are covered including the ceiling and the retry limit,
      the retry loop is driven by a fake launcher through success / grow-then-succeed / grow-forever
      / non-arena-failure, and a real end-to-end spawn is smoke-tested by `make check`.
- [x] **T8 — Build two binaries.** `build/mfsim` and `build/mfsim-worker` from shared objects.
      *Done when:* `make` produces both, `make check` is green, and the worker path is resolved from
      `argv[0]` (overridable by `MF_WORKER`) rather than from the working directory.

## Open decisions

| Decision | Status |
| -------- | ------ |
| CI — Actions or local-only | **Deferred again to 0.3**, where it is now T0 rather than the last task. Twice is enough |
| Config write-back on arena growth | **Decided: yes, and loudly.** The orchestrator rewrites the config file atomically and says so on stderr. Without write-back, "fixed by the next retry" only holds within a single invocation, and the next run pays the same discovery cost. Guarded by `persist_arena_growth` for anyone who wants their config file left alone |
| Huge pages / `mmap` backing | **Deferred to 6.3.** `calloc` is the portable answer and the arena API hides the difference. `TODO(perf)` recorded at the seam |

## Not in this sprint

Background zeroing (the pool refills inline; the worker thread that keeps it stocked needs threading,
which is 6.1). Real per-thread arena sizing (there is one worker arena until there are threads).
`mmap`/`madvise` backing, and any measurement of L1 residency — 6.3 owns that, and there is no hot
loop to measure yet.
