# Sprint 3.3 — Fixture validation

**Epic:** E3 Solo evaluation · **Gate:** **G4 — DEFERRED** · **Status:** `done` — [retro](../retros/3.3-fixture-validation.md)

## Goal

Validate the objective against real decks with measured outcomes: transcribe the 67 precons that
have win rates, rank them with the solo objective, and run **G4** — does the objective rank real
decks in the right order?

## Why this next

3.2 chose the objective, pre-registered a degeneracy check, and got one pass and one failure out of
it. Both results are about *this* project's model rather than about the world, and nothing in E3 can
tell the difference. G4 is the first measurement that can: it is the only place the objective meets
outcomes it did not generate.

**It must be read knowing what 3.2 found**, and the retro's gate section says so in advance rather
than afterwards:

1. **Two of §13.3's four known-bad decks are not caught** — 20 lands at 0.81× a real deck and 60
   lands at 0.94×, both feasible. Precons are built to a sensible land count, so the specific blind
   spot may not bite; a Spearman computed with a known blind spot must be reported with it.
2. **The aggregation error is deck-differential** (3.1): +22% on high curves, −10% on artifact ramp.
   G4 cannot see it and inherits it.
3. **A gate threshold in standard errors leaves the sample size blank** (2.3). Effect size beside
   significance, and the sample size fixed in advance.

## G4, pre-registered

**Written down before any precon has been scored, and committed before the data is touched**, so
the record shows the order. A threshold chosen after seeing the number is not a threshold (2.1),
and a threshold in standard errors with the sample size left blank is not one either (2.3).

### The numbers, fixed now

| | |
| --- | --- |
| **Statistic** | Spearman ρ between the simulator's fitness ordering and Playgroup's win-rate ordering |
| **Corpus** | Precons with **n ≥ 100** tracked games, per §13.2 |
| **Games per deck** | **2,048**, fixed in advance. At σ ≈ 6.3 that is a per-deck standard error near 0.14 on a mean near 30 — half a percent, far inside any spread a ranking could care about |
| **Band** | `MF_RUNG_ALL`; fitness is the max over admissible strategies (§4) |
| **Horizon** | `MF_SOLO_TURNS`, the design's, and not a parameter to search |
| **Effect size** | ρ itself |
| **Significance** | ρ·√(N−1), reported beside ρ and never instead of it |

### The three-way branch, and why there is one

2.3's pass/defer/fail branch was written before the measurement precisely so a coarse instrument
could not be recorded as "no signal exists", and it worked. The same hazard is here in a different
form, so the same shape is used.

| Outcome | Condition | Meaning |
| ------- | --------- | ------- |
| **PASS** | ρ ≥ **0.35** *and* ρ·√(N−1) ≥ 2 | The objective orders real decks, given everything §13.2 says about ordinal-only transfer |
| **FAIL** | ρ ≤ **0.0** | It orders them no better than chance, or backwards. §3 is wrong and gets redesigned — not λ tuned until the numbers look nice |
| **DEFER** | 0 < ρ < 0.35 | A positive but weak signal |

**The defer branch exists for a reason that is written down now rather than found later.** Three
blind spots are already known and recorded in [`gates.md`](../gates.md): flood and screw are not
caught (3.2), the aggregation error is deck-differential at 10–20% (3.1), and the data is
4-player-normalised against a 2-player simulator (§13.2). A weak positive cannot distinguish "the
objective is wrong" from "the model cannot see what this data measures", and those have opposite
consequences. If it defers, the retro says which blind spot it would have to be and what would
separate them.

**0.35 is chosen, not derived, and here is the choice.** Under the null, Spearman's standard error
is about 1/√(N−1); with the ~30–40 decks §13.2's n ≥ 100 filter is expected to leave, that is
roughly 0.17, so 0.35 is about two standard errors — a bar the data can actually clear or miss
rather than one it cannot resolve. §13.2 says to tighten it as the model matures; this is the first
setting of it and the loosest it should ever be.

## Risks carried in

- **The clock, three findings deep** (3.1, 3.2 T1, 3.2 T6). A null-opponent model with a fixed
  horizon prices position at zero. G4 measures a metric that inherits it and cannot correct for it.
- **Flood and screw are not caught** (3.2 T6). If precon rankings look good anyway, that is not
  evidence the blind spot closed.
- **The aggregation error is deck-differential** (3.1), at 10–20%, and G4 cannot see it.
- **Pre-registration protects against fitting a metric to an answer, not against picking a
  degenerate one** (3.1). 3.2 added a degeneracy check; it clears the deck axis and not the
  strategy axis.
- **The metacard carries no amounts** (2.2): draw and cost reduction both assume one. Precons are
  full of both.
- **Precon prices are unfilled** (190 rows) and **win rates unfilled** (67 rows). G4 needs the
  second, and it is transcription work with no shortcut.
