# Sprint 1.3 — Classes, dominance, enrichment

**Epic:** E1 Card pipeline · **Gate:** none · **Status:** `not_started`

## Goal

Turn 37,553 cards into the few thousand *behaviours* the optimiser actually searches over, merge the
dominance chains, enrich what remains, and emit the binary card table with a content hash.

## Why this next

The card set exists and G1 says enough of it can be modelled. What is missing is the reduction that
makes the search space tractable: §7.1 turns cards into classes because Llanowar Elves and Fyndhorn
Elves *are the same object* once a card is a struct, and searching over both is searching a space
full of identical points.

## The blocker that is now resolved

This sprint was deliberately left un-split, because the reduction's shape depends on how many classes
37,553 cards collapse into and nobody had measured it. **Resolved by decision: classification is a
tool that runs inside `preprocess`.** The count is then a by-product of a pass that has to exist
anyway, rather than a measurement someone takes first — T2 produces the number that T3 onward
consume. Design §7.1's "~400 cards collapse toward ~150" is a claim about a *candidate pool*, not
about the whole legal card set, and it should not be assumed to scale.

## The ordering that changed

**The 32-byte card struct comes first now, not last.** It was carried out of 1.2 as unfinished
business; it turns out to be the prerequisite for everything here, because §7.1 does not class cards
*by* the struct — the struct **is** the class. A byte of padding that varies between two otherwise
identical cards splits a class that should be one. This is why packing it against a settled opcode
payload was worth waiting for, and it is why it is T1.

## Exit criteria

- [ ] The card struct is **≤32 bytes**, asserted at compile time (spec: `card_struct.size_target_bytes`)
- [ ] Cards collapsed to equivalence classes by struct identity, with **the class count measured and
      in the run artifact**
- [ ] The class→members mapping retained, so search can collapse and output can expand (§7.1)
- [ ] Dominance computed as an **exact** superset test at ≤ mana cost and ≤ dollar cost, and chains
      merged into tiered classes with a preference-ordered roster (§7.6)
- [ ] Price imputed via dominance for the 3,849 paper cards with no price (§8)
- [ ] Skill floors assigned (§7.4)
- [ ] Binary card table emitted with a content hash stamped into the run artifact (§14.2)
- [ ] `make check` green at ≥95% line and branch

## Tasks

- [ ] **T0 — `--report-unmatched`.** *Carried from 1.2 T6.* The G1 number is in the artifact; the
      ranked list of unmatched clause shapes that says what to build next is not, and came from a
      throwaway script both times it was needed.
      *Done when:* `mfsim preprocess --report-unmatched` prints shapes by frequency, and the top of
      that list matches the retro's table without a script in between.
- [ ] **T1 — The opcode payload and the 32-byte card struct.** *Carried from 1.2 T2.* Cost, colours,
      opcodes, P/T in ≤32 bytes, `_Static_assert`ed.
      *Done when:* the assertion holds, and two cards that differ only in a field the model does not
      carry produce **byte-identical** structs — the property the whole of T2 rests on.
- [ ] **T2 — Equivalence classes, and the measurement.** Collapse by struct identity; keep
      class→members.
      *Done when:* the class count is in the run artifact for all three games, Llanowar Elves and
      Fyndhorn Elves land in one class, and the class→members map round-trips every card.
- [ ] **T3 — Dominance and chain merging.** A dominates B when A's effects are a superset at ≤ mana
      and ≤ dollar cost. Merge along chains in the DAG; incomparable branches stay separate.
      *Done when:* a dominated card is **still reachable** through its merged class's roster on
      overflow — the property §7.6 exists to protect — and multiplicity equals total chain members.
- [ ] **T4 — Price imputation.** The cheapest equivalent-or-better card's price (§8).
      *Done when:* the 3,849 priced-absent paper cards resolve or are explicitly marked unresolvable,
      and an imputed price is never lower than a dominating card's real one.
- [ ] **T5 — Skill floors** (§7.4).
      *Done when:* each class carries a floor, and the assignment rule is a list with a reason per
      entry rather than a heuristic nobody can audit — the standard 1.2 T5 set.
- [ ] **T6 — Precon membership bitmask.** ⚠️ **Has an unmet data dependency — see Decisions.**
- [ ] **T7 — The binary card table.** Replace the JSONL intermediate; content-hash it and stamp the
      hash into every run artifact (§14.2).
      *Done when:* the table round-trips, the hash changes when any input card changes, and a run
      records the hash of the table it actually read.
- [ ] **T8 — Retro and amendments.**

## Decisions

| Decision | Status |
| -------- | ------ |
| Where classification runs | **Inside `preprocess`**, per the user. The class count is a by-product of a pass that must exist, not a prerequisite measurement |
| Struct-first ordering | **Decided above.** The struct is the class key, so T1 precedes T2. This is what the 1.2 carry-over was waiting for |
| **Precon membership data (T6)** | ⚠️ **Open, and it blocks T6 alone.** The bitmask needs ~68 precon decklists and no source is acquired: 1.1 ingested Scryfall bulk only, and EDHREC/Tagger are still unported. Scryfall knows precon *products* but not their contents. **Resolve before T6 or defer T6 to the E1 close** — the rest of the sprint does not depend on it |
| Whether unrepresentable cards are excluded before classing | **Yes**, per §7.9 — the pool is pruned by legality, colour identity and representability. Note this prunes 2,148 commander-legal cards at the current G1 |
| Whether to trust §7.1's ~150 figure | **No.** It describes a candidate pool, not the legal card set. T2 measures rather than assumes |

## Risks carried in

- **G1 must be quoted with its inert share, never bare** (1.2.1). Coverage rises when less is
  simulated, so a coverage improvement that comes with a rise in inertia is not one.
- **A classifier agrees with itself** (1.2, 1.2.1 — twice). Every defect in the opcode work was found
  by interrogating the real export, never by reading the code and never by a failing test. The class
  count and the dominance edges are the next two things that will look plausible and be wrong;
  check both against real cards whose relationship is known independently.
- **Conditional lands are the largest unmatched lever**, and `unless you control a Mountain` is a
  predicate the simulator *could* evaluate against the battlefield. T1's payload design is the moment
  to decide whether a condition field earns its bytes.

## Not in this sprint

Any simulation. The opening phase is E2. This sprint ends with a binary card table and nothing that
reads it.
