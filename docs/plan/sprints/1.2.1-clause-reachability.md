# Sprint 1.2.1 — Clause reachability

**Epic:** E1 Card pipeline · **Gate:** **G1 re-measured** · **Status:** `done` — [retro](../retros/1.2.1-clause-reachability.md)

## Goal

The classifier decides a clause from the first effect keyword it recognises and only *sometimes*
asks whether the model can actually express what it found. Make that question one rule, applied
everywhere, and re-measure G1 against it.

## Why this is a follow-on and not a reopening

1.2 is done and its retro is written; correcting that record in place would destroy it. The same
argument that inserted 0.2.1 after 0.2 applies here, and for a sharper reason: **G1's number is
published**, and a published measurement that quietly changes is worse than one that is superseded
in the open. 0.9357 stands as what was measured, with what was wrong with it recorded beside it.

## What is wrong

Found the way the 1.2 retro said to find things — by asking the real data what the classifier
accepted, not by reading the classifier. The prompt was an observation that dual lands often enter
tapped, which turned out to be the visible corner of a systemic defect.

| | Clauses | Cards | Read as | Should be |
| --- | ---: | ---: | --- | --- |
| Conditional enters-tapped | 161 | 162 | `enters_tapped`, unconditionally | `unmatched` — the condition is real |
| Variable cost reduction | 118 | — | `cost_less`, as if fixed | `unmatched` |
| Variable draw | 123 | — | `draw`, as if fixed | `unmatched` |
| Land fetch without the word "land" | 65 | 64 | `inert` — "tutoring a spell, not ramp" | `fetch_land` |
| Combat- and death-triggered effects | ~2,100 | — | `unmatched` or a concrete opcode | `inert` — the trigger never fires |

Two examples carry the whole argument:

- **`Clifftop Retreat enters tapped unless you control a Mountain or a Plains.`** is recorded as
  entering tapped, full stop. The mana branch already rejects `unless` as inexpressible; the
  enters-tapped branch runs *before* it and does not. The rule existed and was not applied.
- **`Search your library for a Plains or Island card`** is recognised as a land fetch **only
  because "Island" contains the letters l-a-n-d**. Change the card to say `Mountain or Forest` —
  Nature's Lore, Three Visits — and the same effect is classified inert. An accident of English
  spelling is deciding a classification.

## The rule, stated once

Three steps, in order. Steps 1 and 3 are the two halves that were missing.

1. **Reachability.** Does this clause's trigger fire inside the simulated phases? Entering the
   battlefield, casting a spell, the beginning of a turn or step, and playing a land all happen in
   turns 1–4. **Attacking, blocking, dealing combat damage, dying, and an opponent's actions do
   not** — §3 does not simulate combat. A clause gated on an event these phases never run is
   **inert**, whatever it goes on to do.
2. **Shape.** What does it do, in the observable currency: mana, cards drawn, lands, cost.
3. **Expressibility.** If the shape is concrete but the *amount* or the *condition* depends on game
   state this model does not carry, it is **unmatched**. Optionality is not such a condition — a
   policy that declines free ramp is not a policy this design models (§5).

Step 1 subsumes what the draw branch was doing ad hoc, and reverses it: `Whenever this creature
attacks, draw a card` was **unmatched** and becomes **inert**. That is not a convenience. Calling
it unmatched charges the opcode set for a limitation that belongs to the *choice of simulated
phases*, and the gate would then count the same narrowness twice — once as "89% of clauses are
inert" and once as "these clauses are unmodelled".

## Exit criteria

- [x] Reachability, shape and expressibility are three separable, individually tested steps
- [x] Every branch is subject to the expressibility gate; none decides alone
- [x] Land fetch is recognised by land *type*, and a test proves the Island accident is gone
- [x] **G1 re-measured** on the real pool, recorded beside 0.9357 rather than over it
- [x] Every changed assertion from 1.2 listed in the retro with the argument for changing it
- [x] `make check` green at ≥95% line and branch

## Tasks

- [x] **T1 — Reachability.** The event vocabulary, from the data: `enters` 4,906, `beginning of`
      1,990, `you cast` 920 reachable; `attacks` 1,296, `dies` 1,054, `deals combat damage` 662,
      `blocks` 124 not.
      *Done when:* an ETB ramp creature is still a fetch, and a combat-damage draw is inert.
- [x] **T2 — Expressibility, applied everywhere.** One predicate, every branch.
      *Done when:* the conditional lands, variable cost reductions and variable draws are unmatched,
      and a test exists per marker as `every_wording_the_rule_names` already demands.
- [x] **T3 — Land types.** Fetch recognition by basic land type and the word "land".
      *Done when:* `Mountain or Forest` and `Plains or Island` classify identically.
- [x] **T4 — Re-measure G1.** The real pool, the corrected classifier, recorded as a supersession.
- [x] **T5 — Retro and amendments**, including the 1.3 unblock (below).

## Decisions

| Decision | Status |
| -------- | ------ |
| Combat-triggered effects: inert or unmatched? | **Inert.** The trigger is unreachable, so the clause contributes nothing to what is being measured. Charging the opcode set for it double-counts the narrowness of the phases |
| Optional effects (`you may`) | **Expressible.** Assume the beneficial choice; a policy that declines free ramp is not modelled |
| Does the G1 verdict change? | **No.** Measured 0.9325 against a 0.60 threshold, superseding 0.9357. The number was overstated, the call was not |
| Where class classification lives (1.3 blocker) | **In the preprocessing step**, per the user. The class count is then a by-product of a pass that has to exist anyway, rather than a measurement someone takes first. This resolves `class_count_measured` and lets 1.3 be task-split |

## Not in this sprint

Growing the opcode set to cover the unmatched tail. This sprint makes the number honest; it does
not make it bigger.
