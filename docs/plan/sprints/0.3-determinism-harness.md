# Sprint 0.3 — Determinism harness

**Epic:** E0 Foundations · **Gate:** none · **Status:** `done` — [retro](../retros/0.3-determinism-harness.md)

> Renumbered from 0.2 when the memory & process model was inserted ahead of it, then re-planned
> against the 0.2 retro.

## Goal

Counter-based RNG, layered output digests, and the golden-file regression harness — with the
6-way determinism matrix passing on a trivial workload. Still no simulation.

## Why this next

Determinism is built before there is anything to be deterministic about, deliberately. Retrofitting
it means auditing every accumulator written in the meantime, and the reduction-order bug it guards
against is silent — it shows up as low-bit drift nobody notices until a result cannot be reproduced.

The harness is also what makes every later sprint's refactors provable rather than asserted.

## Input from the 0.2 and 0.2.1 retros

- **Arena allocation and fail-fast are in place.** The RNG and digest modules take an arena and have
  no allocation-failure paths to test. Expect fewer error branches than 0.1 would have produced.
- **Watch for branches a refactor has just made dead.** Two survived the arena port by a whole
  sprint before anyone noticed. Re-read the branch report after any port, not just after new code.
- **Do not catch a fatal that owns memory the test cannot reach.** `MF_EXPECT_PANIC` longjmps past
  cleanup, so LeakSanitizer is right to complain. Those cases belong in `tests/smoke.sh`, where a
  real process really does die.
- **Green on the first compile proves nothing.** Where the red cannot be observed first, mutate the
  implementation afterwards and watch the test catch it.
- **`_FORTIFY_SOURCE` folded branches** are 21 of the 22 residual branches. Do not chase them; the
  95% floor has headroom.
- **A covered branch is not a tested branch.** A mutation survived 0.2.1 because a high-water mark
  is only ever written while it is rising, so the comparison and an unconditional assignment are
  indistinguishable until something asks for *less* after the peak. Coverage saw nothing wrong. This
  sprint is full of accumulators, which is the same shape — assert the value after it should have
  stopped moving, not only while it moves.
- **A pool is claimed at a phase boundary, never inside one.** The digest sinks and the reduction
  helper both run per work item. Neither may acquire.
- **The CI decision has now been deferred twice**, both times because the digest did not exist. It
  does after this sprint, so the reason is spent — hence T0 rather than T10.

## Exit criteria

- [x] Counter-based RNG: `(seed, stream, counter)` → value, with no sequential state
- [x] Layered digest emission over semantic output, not text
- [x] Golden-file comparison with a `make golden` update path
- [x] The 6-way matrix (threads 1/4/8 × fresh/resumed) passes on a trivial workload
- [x] `make check` green at ≥95% line and branch

## Tasks

- [x] **T0 — Decide CI. → LOCAL ONLY.** Settled below, under *Open decisions*, with its reason.
      Not deferred, not partially answered: there will be no hosted CI for this repo.
- [x] **T1 — Counter-based RNG (`mf/rng`).** Planned as Philox-style or PCG; **built on splitmix64**,
      whose per-stream sequence is the published one and whose finaliser is the only externally
      checkable value in the module. Explicit streams, pure function of `(seed, stream, counter)`,
      no hidden state. Must be reproducible across thread
      counts by construction, since the stream is keyed by work item rather than by worker.
      *Done when:* the published splitmix64 output sequence is asserted, and the same
      `(seed, stream, n)` yields the same value regardless of call order.
- [x] **T2 — Unbiased bounded draw.** `mf_rng_below(n)` with rejection sampling, not modulo.
      *Done when:* a chi-square test over a small range shows no modulo bias, and the rejection
      branch is covered.
- [x] **T3 — Fisher-Yates shuffle.** Built on T2.
      *Done when:* a permutation-frequency test over a 5-element deck shows all 120 orderings within
      tolerance, and the same seed always yields the same permutation.
- [x] **T4 — Digest primitive.** A non-cryptographic 128-bit hash over a byte stream, stable across
      runs and thread counts.
      *Done when:* incremental hashing matches one-shot hashing, and one frozen vector — cross-checked
      against a reimplementation written from the header alone — pins the byte order, which nothing
      else can see.
- [x] **T5 — Layered digest emission.** Named digest sinks (`preprocess`, `opening`, `solo`,
      `gauntlet`, `run`) that hash **semantic values in fixed index order**, never text and never
      completion order.
      *Done when:* feeding the same values in a different *arrival* order produces the same digest,
      and changing any value changes exactly one layer.
- [x] **T6 — Deterministic reduction helper.** Collect-then-reduce in index order, with integer
      accumulation where the value permits.
      *Done when:* a test that submits results out of order reduces identically to in-order.
- [x] **T7 — Golden-file harness.** Digests written to `tests/golden/`, compared on run, updated
      only via an explicit `make golden`.
      *Done when:* a deliberate value change fails the comparison with a readable diff, and
      `make golden` updates it.
- [x] **T8 — Trivial deterministic workload.** A stand-in "evaluation" (shuffle, draw, sum) with no
      game semantics, wired through the digest layers, so the harness has something to measure
      before the simulator exists. It hangs off `mfsim validate`, which already exercises the memory
      layer, rather than inventing a second subcommand.
      *Done when:* `mfsim validate` emits all five digests alongside the existing `memcheck` record.
- [x] **T9 — The 6-way matrix.** Threads 1/4/8 × {fresh, resumed}. Threading is not built until
      sprint 6.1, so the thread axis is exercised by *simulated* work partitioning — the point is to
      prove the digest is invariant to partition order, which is where the bug would be.
      *Done when:* all six combinations produce byte-identical digests, run by `make check`.

## Open decisions

| Decision | Status |
| -------- | ------ |
| CI — Actions or local-only | **Decided: local only, `make check` is the gate.** See below |
| Digest algorithm | **Decided: in-tree, two-lane, splitmix64's finaliser.** No dependency, and it shares the mixer with `mf/rng` rather than carrying a second copy of the constants |
| Where the trial workload lives | **Decided: its own module, `mf/trial`, not inside the worker.** The six-way matrix has to drive it with partition and resume parameters that no subcommand should expose. `mfsim validate` calls it with a plan of one partition and no resume |
| Do the control files need to be digest-neutral? | **Answered in 0.2: no.** The resolved config and fatal report are transient, carry a pid, and nothing derived from them reaches an artifact |

### T0 in full: there will be no hosted CI

Three reasons, in order of how much they decide it.

**The build is pinned to one machine.** `docs/simulator-spec.yaml` fixes `-mcpu=apple-m1`, and the
design fixes the target host to a single Apple-silicon laptop. A hosted runner would compile
different code with a different toolchain — so a green tick there would say nothing about the binary
that matters, and the determinism invariant is *defined* against this target. CI on other hardware
would not be weaker assurance; it would be assurance about a different program.

**The standing instruction on this repo forbids adding a cloud dependency.** That alone settles it,
and it is the reason the question kept being deferred rather than answered — but it is worth
recording that the technical answer agrees with it independently, so this is not a constraint the
project is working around.

**`make check` is already the gate, and it is the whole gate.** Build, `memcheck`, ASan/UBSan/LSan,
coverage floor, smoke, golden. Nothing a hosted runner would add is missing from it; what is missing
is the *habit*, and that is not a thing CI supplies either.

What that costs, stated plainly: nothing enforces the gate on a machine that has not run it. The
mitigation is `make hook`, which installs a pre-push hook running `make check` — opt-in, one line,
no dependency. Revisit if this ever stops being one person on one machine, which is the condition
that made all three reasons true.

## Not in this sprint

Real threading (sprint 6.1) and real checkpointing (sprint 6.2). The "resumed" axis here replays a
serialised counter, which is the part that determinism depends on — not the full checkpoint schema.
