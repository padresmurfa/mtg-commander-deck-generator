# Sprint 1.2 — Opcode model

**Epic:** E1 Card pipeline · **Gate:** **G1 — opcode coverage** · **Status:** `done` — [retro](../retros/1.2-opcode-model.md)

## Goal

Turn oracle text into opcodes for the modelled subset, fit the card into 32 bytes, and **measure
what fraction of the real 37,553-card pool can actually be represented**. The measurement is the
sprint; everything else serves it.

## Why this next

The card set exists and contains nothing the simulator can act on. And **G1 can kill the project**:
design §13.5 says to measure it in the first slice, because "it is a couple of hours of work and it
can invalidate months". Every sprint after this one assumes the answer is yes.

Thresholds, from [`gates.md`](../gates.md): **≥0.60 sound, ≤0.30 compromised.** Between them is a
judgement call that has to be made out loud. On failure the branch is written down already — grow the
opcode set and re-measure, or stop. Not proceed and hope.

## The decision the number depends on

**What does "representable" mean?** Two readings give answers an order of magnitude apart, so this
is settled before anything is built rather than discovered afterwards in the number.

- *Every word of the rules text is modelled.* Coverage would be a few percent. Nothing in this
  design ever claimed to model Magic; §1 says so explicitly.
- **A card is representable when everything it does *that the simulated phases can observe* is
  modelled.** ← this one.

The second is the only reading consistent with the rest of the design. §3 evaluates turns 1–4 exactly
and everything later in aggregate, and the opening is a **feasibility gate** — can this deck cast its
spells and reach turn 5 functional. What a card does on turn 9 is not observed by that gate, so a
vanilla 4/4 is *fully* representable: it is a cost, a colour requirement and a body, and the model
has all three.

What the phases actually observe, and therefore what the opcode set must cover:

| Observable | Why |
| ---------- | --- |
| Mana produced — how much, which colours, tapped or not | The whole of whether a spell can be cast |
| Cost and colour requirements | Already modelled (sprint 1.1 pips) |
| Cards drawn | Changes what is available to cast |
| Lands fetched or put onto the battlefield | Ramp is the other half of sequencing |
| Cost reduction | Changes castability directly |
| Nothing else, yet | Combat, removal, counters and the stack are not simulated in the opening |

**A card is unrepresentable when it has a clause the opening phase *would* observe and the opcode
set cannot express it** — a conditional mana producer with rules the model does not have, a draw
effect gated on something unmodelled. A card whose only unmodelled text is irrelevant to the
observed phases is representable, and saying otherwise would understate the pool by excluding most
of Magic for no benefit.

**This reading is recorded in the retro with the number**, because the number means nothing without
it, and a later sprint that widens the simulated phases must re-measure rather than inherit it.

## Exit criteria

- [x] An opcode encoding for the observable set above, with a decided representation
- [x] Oracle text compiled to opcodes, clause by clause, with unmatched clauses counted by shape
- [ ] The card struct is **≤32 bytes**, asserted at compile time (spec: `card_struct.size_target_bytes`)
- [x] **G1 measured on the real pool** and recorded in the retro: the fraction, the threshold, and
      the pass/fail call
- [ ] The cards that failed are *listed by reason*, so "grow the opcode set" is actionable rather
      than a slogan
- [x] `make check` green at ≥95% line and branch

## Tasks

- [x] **T1 — Read the oracle text.** `mf/scryfall` does not read `oracle_text` yet, and it is on the
      faces for double-faced cards.
      *Done when:* text arrives for single- and double-faced cards, and the arena still holds only
      the card set rather than the file.
- [ ] **T2 — The opcode set. → CARRIED TO 1.3.** The enum exists; the 32-byte *payload* does not.
      It constrains a runtime card nothing executes yet, and the emitted table is the JSONL
      intermediate 1.3 replaces — so packing bits now would mean packing them twice, against a
      payload G1's unmatched tail is about to change. 1.3 decides the layout once, alongside the
      binary table it already owns.
- [x] **T3 — Clause splitting.** Oracle text into clauses, on sentence and line boundaries, with
      reminder text in parentheses dropped.
      *Done when:* the awkward real cases are fixtures — a card with no text, one with only
      reminder text, one whose ability spans two lines.
- [x] **T4 — The compiler.** Clause → opcode, or → unmatched-with-a-reason.
      *Done when:* each opcode has a test built from a real card's exact text, and an unmatched
      clause records enough to group by shape.
- [x] **T5 — Inert-clause classification.** The half that decides the number: a clause the opening
      phase cannot observe is not a failure to model.
      *Done when:* the rule is a list with a reason per entry, not a regex nobody can audit.
- [~] **T6 — Measure G1. → HALF DONE.** The number is in the run artifact, which is the half that
      gates the project. The `--report-unmatched` mode is not built: the ranking in the retro was
      produced by a script against the export, so the list that guides the *next* sprint is not
      something `mfsim` can print. Carried.
- [x] **T7 — Gate validation and retro.** The measured fraction, the threshold, the call, and — if
      it fails — which branch was taken.

## Decisions

| Decision | Status |
| -------- | ------ |
| What "representable" means | **Decided above:** everything the simulated phases can observe. Recorded with the number, since the number is meaningless without it |
| Coverage weighting | **Decided: unweighted over the legal commander pool.** Weighting by popularity would import exactly the prior `no_popularity_prior` forbids, so the unweighted fraction is both the honest headline and the only one measured |
| Whether to fail fast on an unmatched clause | **No.** Unmatched is data, not an error — the whole point is to count them and rank what to build next |

## Not in this sprint

Equivalence classes, dominance chaining, skill floors, price imputation, the binary card table —
all 1.3. Any simulation: the opcodes are emitted and counted here, not executed.
