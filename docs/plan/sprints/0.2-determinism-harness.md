# Sprint 0.2 — Determinism harness

**Epic:** E0 Foundations · **Gate:** none · **Status:** `active`

## Goal

Counter-based RNG, layered output digests, and the golden-file regression harness — with the
6-way determinism matrix passing on a trivial workload. Still no simulation.

## Why this next

Determinism is built before there is anything to be deterministic about, deliberately. Retrofitting
it means auditing every accumulator written in the meantime, and the reduction-order bug it guards
against is silent — it shows up as low-bit drift nobody notices until a result cannot be reproduced.

The harness is also what makes every later sprint's refactors provable rather than asserted.

## Input from the 0.1 retro

- The **allocation seam** pattern generalises: any failure path a test cannot otherwise reach gets a
  seam. Apply it here to digest and checkpoint I/O rather than discovering the gap at the coverage
  gate.
- **`_FORTIFY_SOURCE` folded branches** cap achievable branch coverage below 100%. Do not chase it;
  the 95% floor has headroom.
- **The CI decision is due this sprint** — the digest check now becomes a thing CI could enforce.

## Exit criteria

- [ ] Counter-based RNG: `(seed, stream, counter)` → value, with no sequential state
- [ ] Layered digest emission over semantic output, not text
- [ ] Golden-file comparison with a `make golden` update path
- [ ] The 6-way matrix (threads 1/4/8 × fresh/resumed) passes on a trivial workload
- [ ] `make check` green at ≥95% line and branch

## Tasks

- [ ] **T1 — Counter-based RNG (`mf/rng`).** Philox-style or PCG with explicit streams. Pure
      function of `(seed, stream, counter)`; no hidden state. Must be reproducible across thread
      counts by construction, since the stream is keyed by work item rather than by worker.
      *Done when:* known-answer tests pass against fixed vectors, and the same `(seed, stream, n)`
      yields the same value regardless of call order.
- [ ] **T2 — Unbiased bounded draw.** `mf_rng_below(n)` with rejection sampling, not modulo.
      *Done when:* a chi-square test over a small range shows no modulo bias, and the rejection
      branch is covered.
- [ ] **T3 — Fisher-Yates shuffle.** Built on T2.
      *Done when:* a permutation-frequency test over a 5-element deck shows all 120 orderings within
      tolerance, and the same seed always yields the same permutation.
- [ ] **T4 — Digest primitive.** A non-cryptographic 128-bit hash over a byte stream, stable across
      runs and thread counts.
      *Done when:* known-answer tests pass and incremental hashing matches one-shot hashing.
- [ ] **T5 — Layered digest emission.** Named digest sinks (`preprocess`, `opening`, `solo`,
      `gauntlet`, `run`) that hash **semantic values in fixed index order**, never text and never
      completion order.
      *Done when:* feeding the same values in a different *arrival* order produces the same digest,
      and changing any value changes exactly one layer.
- [ ] **T6 — Deterministic reduction helper.** Collect-then-reduce in index order, with integer
      accumulation where the value permits.
      *Done when:* a test that submits results out of order reduces identically to in-order.
- [ ] **T7 — Golden-file harness.** Digests written to `tests/golden/`, compared on run, updated
      only via an explicit `make golden`.
      *Done when:* a deliberate value change fails the comparison with a readable diff, and
      `make golden` updates it.
- [ ] **T8 — Trivial deterministic workload.** A stand-in "evaluation" (shuffle, draw, sum) with no
      game semantics, wired through the digest layers, so the harness has something to measure
      before the simulator exists.
      *Done when:* `mfsim validate` runs it and emits all five digests.
- [ ] **T9 — The 6-way matrix.** Threads 1/4/8 × {fresh, resumed}. Threading is not built until
      sprint 6.1, so the thread axis is exercised by *simulated* work partitioning — the point is to
      prove the digest is invariant to partition order, which is where the bug would be.
      *Done when:* all six combinations produce byte-identical digests, run by `make check`.
- [ ] **T10 — Decide CI.** GitHub Actions running `make check`, or local-only. Record the decision
      and its reason in this file, then in the retro.

## Open decisions

| Decision | Status |
| -------- | ------ |
| CI — Actions or local-only | **Due this sprint (T10).** Carried from 0.1, where the thing CI would enforce did not yet exist |
| Digest algorithm | Free choice; must be stable, fast, and not require a dependency. xxHash128 or a SplitMix-based construction, written in-tree |

## Not in this sprint

Real threading (sprint 6.1) and real checkpointing (sprint 6.2). The "resumed" axis here replays a
serialised counter, which is the part that determinism depends on — not the full checkpoint schema.
