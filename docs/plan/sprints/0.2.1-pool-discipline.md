# Sprint 0.2.1 — Pool discipline & alignment

**Epic:** E0 Foundations · **Gate:** none · **Status:** `done` — [retro](../retros/0.2.1-pool-discipline.md)

> A follow-on to 0.2, not a reopening of it. 0.2 is `done` and its retro is written; correcting
> that record in place would destroy it. The memory model gained four requirements after the
> retro was filed, and they are small, related, and load-bearing enough to be a sprint of their
> own rather than a footnote in 0.3.

## Goal

Make the pool a **fixed, configured resource that dies when it runs out** — like the arena, and
handled by the orchestrator the same way. Give it two disciplines, heap and stack. And make the
arena's alignment contract something the code enforces rather than something the comments claim.

## Why this, and why now

**Running dry was a miss; it should be a death.** 0.2's pool made another arena when it was empty
and counted a miss. That is the shape of every design this project has otherwise rejected: a
recoverable environmental failure, with a counter nobody reads and an unbounded footprint behind
it. The arena already had the right answer — a fixed capacity, a fatal, a report, and an
orchestrator that grows the number and relaunches. The pool should have the same answer, and the
depth should be a config parameter for the same reason `arena_bytes` is one: it is a cache that
converges, not a guess that has to be right.

**Depth is not the only thing a pool needs to know.** A pool whose arenas are borrowed and
returned in any order and a pool that models a call stack are different objects with different
invariants, and pretending otherwise loses the only invariant worth having. A stack pool can check
that release is the mirror of acquire, and a bug in frame lifetime dies at the frame that caused
it rather than three phases later. A heap pool cannot check that, so it should not pretend to.

**Acquiring is not free, so nothing should acquire often.** Everything the pool makes cheap is
paid for on release — the reset, and the zeroing. A loop that claims and releases per item spends
that on every item. The rule this sprint adopts is that a pool is claimed at a *phase* boundary,
not inside one, and the counter that would expose a violation is emitted rather than left to
review. The per-game path takes an arena that was claimed before the loop started; that is not
new, it is what `no_io_in_loop` already implies, and it now has a number attached.

**Alignment was claimed, not enforced.** `mf_arena_alloc_aligned`'s header says `align` must be a
power of two no larger than a cache line. Nothing checked. A zero would have been diagnosed as an
arena too small — sending the orchestrator off to grow an arena over a caller's bug — and a
request above the payload's own alignment would have returned an address that was not aligned at
all, quietly. Both are wrong answers rather than slow ones.

## Input from the 0.2 retro

- **`mf/pool` is exercised but barely used.** Still true, and it is why changing its contract now
  costs one caller instead of twenty. The window closes as soon as there is a real evaluation.
- **Watch for branches a refactor has just made dead.** The miss path and the release-past-depth
  path both disappear here. Re-read the branch report rather than trusting the total.
- **Do not catch a fatal that owns memory the test cannot reach.** Pool exhaustion is a fatal
  raised by an object the test built. `MF_EXPECT_PANIC` around it leaks the pool's arenas — so the
  exhaustion cases that own memory belong in `tests/smoke.sh`, with a real process and a real
  exit code.

## Exit criteria

- [x] A pool holds exactly `depth` arenas, created and zeroed before the first acquire, and never
      creates another
- [x] Acquiring from an exhausted pool kills the process with its own exit code and a report
      naming the pool, its depth and its kind
- [x] `MF_POOL_STACK` rejects an out-of-order release as a broken invariant; `MF_POOL_HEAP`
      accepts one
- [x] The orchestrator grows the depth that the report names and relaunches, exactly as it does
      for `arena_bytes`, and persists it
- [x] `mf_arena_alloc_aligned` rejects an alignment it cannot honour instead of honouring it
      approximately
- [x] `make check` green at ≥95% line and branch

## Tasks

- [x] **T1 — The alignment contract.** `MF_ARENA_ALIGN` derived from `alignof(max_align_t)` rather
      than asserted to equal it. `mf_arena_alloc_aligned` treats a zero, a non-power-of-two, or an
      alignment above `MF_ARENA_MAX_ALIGN` as a broken invariant.
      *Done when:* each of the three rejections is a test, the tests assert **addresses** rather
      than offsets, and a static assertion ties `MF_ARENA_ALIGN` to `alignof(max_align_t)` so a
      port to a machine that disagrees fails to compile rather than to run.
- [x] **T2 — `mf/panic`: the pool fatal.** `MF_EXIT_POOL` (73) and `mf_panic_pool(name, kind,
      depth)`. The report carries `pool`, `kind`, `capacity`, `used`, `wanted` and `need`, so the
      orchestrator reads a pool shortfall with the arithmetic it already has.
      *Done when:* the report parses, `need` is `depth + 1`, and the human message names the kind.
- [x] **T3 — `mf/pool`: fixed depth, two kinds.** `mf_pool_create(home, name, kind, capacity,
      depth)`. All arenas up front; `live` and `live_high_water` replace `available` and `misses`;
      `acquires` counts churn. Release is identified by pointer, not by name.
      *Done when:* exhaustion is fatal, a stack pool refuses an out-of-order release, a heap pool
      permits one, releasing a stranger or releasing twice is fatal, and `live_high_water` is the
      peak rather than the last value.
- [x] **T4 — `mf/config`: the depth knobs.** `heap_pool_depth`, `stack_pool_depth`, and
      `pool_max_depth` as the ceiling for both. `persist_arena_growth` becomes `persist_growth`,
      since it now persists more than an arena size.
      *Done when:* the keys round-trip, each range is enforced, a ceiling below either depth is
      rejected after the loop, and `arena_bytes`'s default is small enough that the eager pools do
      not reserve most of a gigabyte before doing anything.
- [x] **T5 — `mf/orch`: grow the knob the report names.** `mf_orch_plan_next` fills an
      `mf_orch_growth` rather than one `size_t`. Exit 70 grows `arena_bytes`; exit 73 grows the
      depth matching the report's `kind`. A kind the orchestrator does not recognise is not
      retried — the safe answer for a resource nobody registered.
      *Done when:* the planner's table covers both resources, both ceilings, the retry limit, and
      the unrecognised kind, and the retry loop is driven through a pool growth by the fake
      launcher.
- [x] **T6 — The worker uses both.** `validate` holds two heap arenas at once and releases them in
      acquisition order — which is what a heap pool is *for*, and what a stack pool would refuse —
      then nests stack-pool frames and unwinds them.
      *Done when:* the `memcheck` record reports both pools, and `smoke.sh` drives a run from
      `stack_pool_depth: 1` up to what the work needs and sees it persisted.
- [x] **T7 — Retro and amendments.** Design §10 and the spec's `invariants.arena_allocation` and
      `parameters.memory` updated in the same change. `status.yaml` back to 0.3.

## Open decisions

| Decision | Status |
| -------- | ------ |
| One arena capacity or one per pool | **Decided: one.** `arena_bytes` sizes every pooled arena. Two capacities would need the report to say which arena it was, which is a name table between the worker and the orchestrator — rot for a distinction nothing yet needs. Revisit when a real evaluation makes frame arenas visibly different from evaluation arenas |
| Depth 0 | **Decided: illegal.** It used to mean "do not pool this"; with exhaustion fatal it would mean "acquiring is always fatal", which is a config that can only be a mistake. Range starts at 1 |
| Enforcing the no-churn rule in code | **Decided: no, count it.** A `seal` that made acquiring fatal during a hot phase has no caller yet, and machinery with no caller is the speculation this sprint is otherwise removing. `acquires` is emitted; the rule is in design §10 |

## Not in this sprint

Per-pool arena capacities (see above). Background zeroing, still 6.1. Any use of the stack pool
beyond `validate` — there are no call frames to model until there is a simulation.
