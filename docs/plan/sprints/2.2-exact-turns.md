# Sprint 2.2 — Exact turns 1–4

**Epic:** E2 Opening phase · **Gate:** none · **Status:** `done` · [retro](../retros/2.2-exact-turns.md)

## Goal

Turns 1–4, exactly: land drops, mana availability, castability and sequencing, ending in a state
vector §3 can score.

## Why this next

G2 says the hand is dealt honestly. It says nothing about what happens next — and the opening phase
is a **feasibility gate**: *can this deck cast its spells and reach turn 5 functional*. That is the
question the entire opcode model was built to answer, and nothing has asked it yet.

It is also where `mf/trial` finally goes. That stand-in has carried the determinism matrix since 0.3
and exists to be deleted the moment a real phase exists.

## Exit criteria

- [x] A turn loop: untap, draw, land drop, main phase — for four turns
- [x] Mana availability computed from the opcode set, **including whether a land entered tapped**
- [x] Castability decided **pip by pip**, never by converted cost
- [x] A greedy sequencing policy, and an end-of-phase state vector
- [x] Land-drop probabilities checked against the closed form (§13.1) — **worst 1.74σ against 5σ**
- [x] `mf/trial` deleted and the determinism matrix running on the real opening phase
- [x] `make check` green at ≥95% line and branch — **10,143 checks, line 100.00%, branch 95.70%**

## Decisions, settled before the code

All three were open at planning. They are recorded here **before any of the sprint was written**,
because two of them change what gets built and the third is a tolerance, which is worthless chosen
afterwards.

### On the play or on the draw — **both, alternating by game index**

Even game indices are on the play, odd on the draw. A fixed choice was rejected, and not because it
is inelegant: **it would change the ranking, not merely the level.** On the draw is worth about one
extra card by turn 4, and that card is worth far more to a slow, expensive deck than to a cheap one
— so fixing the choice biases the objective *differentially*, which is precisely the failure G4 is
supposed to catch and would not.

Parity assignment is exactly 50/50 for an even sample count, so it is proportional stratification
rather than randomisation, and it has *less* variance than assigning at random. It also satisfies
§7.8's common-random-numbers rule directly: game `g` is on the play for every candidate, so two
decks compared at the same game index faced the same conditions.

§7.8 also says each *matchup* runs both ways with mirrored seeds. That is the right rule for E5,
where the pairing is between candidates. Here the pairing would be between play and draw on the same
shuffle, which for a fixed compute budget gives fewer independent shuffles and a worse estimate of
the mean — the only thing it estimates better is the play-vs-draw difference, which nothing wants.

### What the state vector holds — integers, and the threshold is not one of them

§3 asks for "mana available, cards in hand, board presence, engine pieces online", and a **binary
gate with a low bar whose threshold is conditional on the strategy under test**.

So the vector holds counts and the gate holds the numbers. The vector is:

`lands`, `mana` (producible entering the next turn), `colours`, `spells` cast, `permanents`,
`hand`, `missed_drops`, `mana_spent`, `mana_wasted`, `mulligans`, `on_play`.

Every field is a `uint8`; nothing is a float, so no reduction can reorder it (§17.1). `mana_wasted`
is there because §3's stated reason for simulating these turns exactly is sequencing — "whether the
tapland arrived on the turn you had nothing to cast" — and that is the only field that can see it.

**The threshold is a separate parameterised predicate**, defaulting to *3 mana entering turn 5 and
at least one spell cast*. That is §3's "low bar" and the exact negation of §7.8's early-termination
example, "turn 4, one land, nothing castable". Keeping it out of the vector is what lets §5's five
rungs disagree about it without recomputing anything.

### Tolerance for T6 — **5σ per cell, fixed here, before measuring**

`SE = sqrt(p(1-p)/N)`, the same rule and the same constant as G2. Consistency is worth more than
optimising the constant for a smaller family of cells, and re-deriving a threshold per measurement
is how a threshold ends up being chosen to fit.

T6 must also be unable to pass vacuously — the 2.1 defect — so a zero-sample run fails.

## What the closed form for land drops actually is

§13.1 lists "P(made all land drops through turn T)" as a closed form, citing
`computeLandDropProbabilities` in the legacy tree. That function's comment claims the conjunction
and its body computes only the last term: P(≥ T lands among the first `T+6` cards). Those are
different events, and the conjunction is a subset, so the comment looked like it overstated the
result.

**It does not. They are equal, and the reason is worth writing down** — checked by exact rational
arithmetic against brute-force enumeration before any of this sprint was built:

> Exactly one card is seen per turn, so `L(t) − L(t−1) ∈ {0,1}`. The requirement grows by exactly
> one per turn too. So `L(t) ≥ t` implies `L(t−1) ≥ t−1`, the events are **nested**, and the
> conjunction collapses to its last term.

Two consequences, both load-bearing:

- The identity holds **only for the pure draw step**. Any extra card drawn, or any land put onto the
  battlefield by a spell, breaks the nesting immediately — so T6 measures against a deck that does
  neither, and that restriction is the test's precondition rather than a convenience.
- It means T6's oracle is the *same* hypergeometric family as G2's rather than an independent one.
  What it adds is the code path: the turn loop's draw step and the land-drop rule, which G2 never
  touched.

## Risks carried in

- **A gate must be unable to pass vacuously** (2.1). The zero-sample case reported agreement it had
  never observed. Ask it of T6.
- **The bottoming rule is a guess** (2.1) with no oracle. It affects every hand this sprint plays.
- **Do not treat a class as a card** (1.3). Nothing here expands, but sequencing is the first thing
  that reasons about specific cards rather than counts.
