# Sprint 1.1 — Acquisition & oracle normalisation

**Epic:** E1 Card pipeline · **Gate:** none (G1 is 1.2) · **Status:** `planned`

## Goal

Turn Scryfall's bulk data into a normalised, `oracle_id`-keyed card set with resolved legality,
colour identity and a minimum paper price — the input every later epic treats as given.

## Why this next

E0 is finished: the memory model, the process model and the determinism harness are all in place,
and the harness has nothing but a stand-in to measure. This is the first sprint that produces
something real, and it is the one every other epic depends on — a deck is a set of cards, and until
cards exist there is nothing to simulate, search over or price.

It also has the shortest path to the project's first gate. **G1 (opcode coverage, sprint 1.2)** asks
whether enough of a real commander's card pool can be modelled at all, and it cannot be asked until
there is a real card pool to ask it about.

## Input from the 0.3 retro

- **The determinism harness is calibrated but unproven.** The six-way matrix runs against
  `mf/trial`, which has no game semantics. The first *real* data through the digest layers is the
  card table — so `preprocess` should feed the `preprocess` layer for real, and the golden file
  gains its first meaningful row.
- **A covered branch is not a tested branch.** Parsing is where this bites hardest: a field reader
  that is exercised by every fixture and asserted by none looks fully covered.
- **Mutation testing found four tests that passed for the wrong reason.** Budget for it here; a
  parser is mostly branches, so the coverage number will look reassuring long before the tests are.
- **No CI.** `make check` before every push; `make hook` if you want it enforced.
- **The stand-in is deleted in E2, not here.** `mf/trial` and its golden rows stay until there is a
  real opening phase.

## Exit criteria

- [ ] Scryfall bulk data ingested from a local file into the card set
- [ ] Cards grouped by `oracle_id`; printings are never entities
- [ ] Minimum price across paper-legal non-foil printings, per `oracle_id`
- [ ] Commander legality and colour identity resolved per card
- [ ] The set is emitted with a content hash and re-reads identically
- [ ] `make check` green at ≥95% line and branch

## Tasks

*(To be split at sprint start, after the two open decisions below are settled — they change what the
tasks are. Sketch only, deliberately not ticked into a plan the decisions could invalidate.)*

- **Decide the two open decisions.** First, not last. Both change the shape of every task under them.
- **A JSON reader that survives Scryfall.** The bulk file is ~500 MB of one array. `mf/json` parses
  a document into an arena, which is the wrong shape at that size — this needs a streaming or
  chunked path, and that is a real design decision rather than a tuning one.
- **The printing → oracle grouping.** Group, then reduce to one record per `oracle_id`.
- **Price minimisation.** Across paper-legal non-foil printings only; absent prices are absent here
  and imputed in 1.3, not guessed now.
- **Legality and colour identity.** Both are given by Scryfall; the work is representing them in
  something that will fit a 32-byte card struct later.
- **Emission and content hash.** The card table is an *input* to the deterministic core, so its hash
  is what makes "same seed + config + card table" checkable at all.
- **Fixtures.** A small hand-built bulk file with the awkward cases in it: a card with only foil
  printings, a card with no price at all, a double-faced card, a card whose printings disagree about
  legality.

## Open decisions

| Decision | Status |
| -------- | ------ |
| **Where preprocessing runs — C or Node** | **Open, and it must be answered first.** `simulator-design.md` §8 says "a Node stage, run weekly", written when the project had a Node app around it. It does not any more: the app was replaced by a C CLI in 0.1, and `CLAUDE.md` §6 says the Scryfall/EDHREC/Tagger logic is *ported* in E1 and the reference tree deleted afterwards. These two cannot both be right. Recommendation: **C**, because a second toolchain is a second thing to install, version and keep deterministic — but this is a design amendment either way, and §8 changes in the same commit as the answer |
| **Whether `preprocess` fetches or consumes** | **Open.** Recommendation: **consumes.** The card table is an input to a deterministic core, so acquisition should be a separate, explicitly-invoked step — a subcommand that downloads is a subcommand whose output depends on the day it ran. `mfsim preprocess --bulk <file>` keeps the deterministic part deterministic and leaves fetching to one documented command |
| Streaming vs. document parsing | Follows from the size of the bulk file; decide with the first task, not before |
| Whether `reference/legacy-ts/` can be deleted | **Not yet.** `CLAUDE.md` §6 puts that decision in the E1 retro, once the acquisition logic is genuinely ported |

## Not in this sprint

Opcodes and the card struct (1.2, and G1). Equivalence classes, dominance chaining, skill floors,
price imputation and the binary card table (1.3). EDHREC and Tagger — Scryfall alone is enough to
reach G1, and pulling in three sources at once makes it unclear which one a defect came from.
